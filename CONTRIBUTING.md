# Contributing

The operator has published releases, and its Kubernetes API is `v1alpha1`. Review the
[release notes](https://github.com/alexandrust88/openbao-config-operator/releases) for compatibility
changes. Open an issue to discuss larger changes before writing code.

## Before you start

- Read [docs/architecture.md](docs/architecture.md). It is the source of truth for the design.
- Read the [ADRs](docs/adr/). A change that contradicts one needs a new ADR.
- Check [docs/kinds.md](docs/kinds.md) for the name, group and phase of a kind you want to add.
- Coding agents and humans follow the same rules, listed in [AGENTS.md](AGENTS.md).

## Development setup

You need Go (version in `go.mod`), Docker, kubectl and, for e2e tests, Helm. Tools such as
`controller-gen`, `setup-envtest`, `golangci-lint` and kind are installed into `./bin` by the
Makefile. Integration tests need a `bao` binary (OpenBao) on the `PATH` or in `BAO_BIN`; they skip
when it is absent. `make bao` downloads the pinned OpenBao release into `./bin`.

| command | what it does |
|---------|--------------|
| `make build` | regenerates, formats, vets and builds `./bin/manager` |
| `make test` | runs the unit and envtest tests |
| `make lint` | runs golangci-lint |
| `make check` | runs the fast subset of the pull request gate: formatting, vet, module check, lint, tests, docs examples, generated files, API coverage and the chart lint and schema checks |
| `make test-integration` | runs every integration scenario against `bao server -dev` |
| `make test-e2e` | creates a kind cluster, builds the operator image, runs the e2e tests and deletes the cluster |

What each check proves, and what it does not, is in the
[verification guide](docs/project/verification.md).

`make manifests generate chart-sync samples` regenerates the CRDs, RBAC, deepcopy code, the chart
copies and `examples-generated/`. Commit the generated files; CI runs `make verify-generated` and
fails when regenerating produces a diff.

To try an unreleased change on a kind cluster, for example the one the
[quickstart](docs/get-started/quickstart.md) creates, build the image and install the chart from the clone:

```sh
make docker-build IMG=openbao-config-operator:dev
kind load docker-image openbao-config-operator:dev --name openbao-quickstart
helm upgrade --install openbao-config-operator charts/openbao-config-operator \
  --namespace openbao-config-operator --create-namespace \
  --set image.repository=openbao-config-operator --set image.tag=dev
```

## Chart maintenance

The chart README is published on Artifact Hub. Keep it focused on installation, configuration,
upgrades and support; document contributor workflows here.

CRD templates and manager RBAC rules are generated. Update the API markers or RBAC sources,
then run these commands from the repository root:

```sh
make manifests generate chart-sync
make helm-lint
bin/helm unittest charts/openbao-config-operator
```

`make chart-sync` runs `hack/chart/sync-crds.sh`, which copies `config/crd/bases` into the chart CRD
templates and resource list, `hack/chart/sync-rbac.sh`, which builds the manager rules from
`config/rbac/role.yaml` and `hack/chart/rbac-required.yaml` (it needs `jq`), and
`hack/chart/sync-crd-kustomization.sh`. The unit tests need the
[helm-unittest](https://github.com/helm-unittest/helm-unittest) plugin; CI installs it, so install it
locally before you run them. Commit the generated files with their source changes.

## Pull requests

- Run `make check` before you open the pull request. CI also runs the integration, namespace,
  live-kit, conformance, chart and e2e checks.
- Keep a pull request to one change. Do not mix refactors or reformatting with features.
- Add or update tests: unit tests for adapter `Desired` and `FieldSpec` behaviour, and an
  integration test against `bao server -dev` for a new kind.
- Update [docs/kinds.md](docs/kinds.md) and add an example under `examples/` for a new kind. The
  every-field samples in `examples-generated/` are generated by `make samples`; do not edit them by hand.
- The pull request title is a [conventional commit](https://www.conventionalcommits.org), for
  example `feat(secrets): add TransitCacheConfig`; the `Conventional commit title` check enforces it.
  The title becomes the squash commit subject and the description its body, so put footers such as
  `BREAKING CHANGE:` at the end of the description.
- Comments explain why, not what. Exported identifiers get a short doc comment.
- Never log or store tokens, secret values or OpenBao response bodies.

## Reporting bugs

Open an issue with the operator version, the OpenBao version, the resource YAML
(without secret values) and the resource's status conditions. Security problems go through
[SECURITY.md](SECURITY.md), not public issues.
